## A useful starting point

A good default lets someone begin before they understand every option. The first screen should answer the ordinary question, rather than present all the machinery that could answer an unusual one.

## Prefer one clear path

Choose the behavior that serves most visits. Put an uncommon alternative nearby, but do not make every reader decide between equivalent routes before seeing anything useful.

Defaults are not restrictions. The important distinction is whether a setting exists for a real need or merely because the implementation made it easy to expose. The next part considers how an interface can reveal those alternatives gradually.
